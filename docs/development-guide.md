## Quick Start (Docker-based)

```bash
# 1. Clone the repository
git clone https://github.com/makeplane/plane.git
cd plane

# 2. Run setup script (generates .env files, Django SECRET_KEY)
chmod +x setup.sh
./setup.sh

# 3. Configure environment
# Edit web/.env and space/.env:
echo "NEXT_PUBLIC_API_BASE_URL=http://localhost" >> ./web/.env
echo "NEXT_PUBLIC_API_BASE_URL=http://localhost" >> ./space/.env

# 4. Start external services (PostgreSQL, Redis, MinIO)
docker compose -f docker-compose-local.yml up -d

# 5. Install frontend dependencies
yarn install

# 6. Start development servers
yarn dev
```

This starts:
- **Web app** at `http://localhost:3000`
- **Space app** at `http://localhost:4000`
- **API server** at `http://localhost:8000` (via Docker)

## Full Docker Development

For running everything in Docker (no local Node/Python needed):

```bash
# Setup and start all services
./setup.sh
docker compose up -d
```

Services started:
| Service | Port | Description |
|---------|------|-------------|
| web | 3000 | Main dashboard (Next.js) |
| space | 4000 | Public sharing app (Next.js) |
| api | 8000 | Django REST API |
| worker | - | Celery background worker |
| beat-worker | - | Celery scheduled tasks |
| plane-db | 5432 | PostgreSQL 15.2 |
| plane-redis | 6379 | Redis 6.2.7 |
| plane-minio | 9000 | MinIO (S3-compatible storage) |
| proxy | 80 | Nginx reverse proxy |

```bash
docker compose exec api python manage.py collectstatic    # Collect static files
```

## Project Structure for Development

### Frontend Development (web/, space/)

**Adding a new page:**
1. Create file in `web/pages/[workspaceSlug]/...`
2. Add header component in `web/components/headers/`
3. Use appropriate layout (`AppLayout`, `SettingsLayout`, etc.)
4. Import the page type from `types/app.d.ts`

**Adding a new component:**
1. Create in `web/components/<feature>/`
2. Export from component index if shared
3. Use MobX store via `useMobxStore()` hook
4. Call services for API operations

**Adding a new API service:**
1. Create in `web/services/`
2. Extend `APIService` base class
3. Add SWR fetch keys in `constants/fetch-keys.ts`
4. Use in MobX store or component

**Adding a new MobX store:**
1. Create in `web/store/`
2. Define interface and class
3. Register in `store/root.ts`
4. Access via `useMobxStore()` hook

### Backend Development (apiserver/)

**Adding a new model:**
1. Create in `apiserver/plane/db/models/`
2. Register in `plane/db/models/__init__.py`
3. Run `python manage.py makemigrations`
4. Run `python manage.py migrate`

**Adding a new API endpoint:**
1. Create view in `plane/api/views/`
2. Create serializer in `plane/api/serializers/`
3. Add URL pattern in `plane/api/urls/`
4. Register URL file in `plane/api/urls/__init__.py`
5. Add permission class if needed

**Adding a background task:**
1. Create in `plane/bgtasks/`
2. Use `@shared_task` decorator
3. Call with `.delay()` from views

## Testing

### Backend Tests
```bash
# Run all tests
docker compose exec api python manage.py test

# Run specific test file
docker compose exec api python manage.py test plane.tests.api.test_issue

# Test files location: apiserver/plane/tests/api/
```

Test files cover: authentication, workspaces, projects, issues, cycles, modules, views, states, assets, OAuth.

### Frontend Testing
No dedicated test framework configured in this version. Linting serves as primary code quality check.

## Code Style

- **Frontend:** ESLint (eslint-config-next) + Prettier
- **Backend:** Python standard (PEP 8)
- **Commit conventions:** Not strictly enforced, descriptive messages preferred

## Monorepo Architecture

```
Turbo Pipeline (turbo.json):
  build: depends on ^build (build dependencies first)
  develop: persistent, no cache
  lint: no dependencies

Yarn Workspaces:
  web, space             → Next.js applications
  packages/*             → Shared libraries

Build Order:
  1. packages/tsconfig
  2. packages/eslint-config-custom
  3. packages/tailwind-config-custom
  4. packages/editor/core
  5. packages/editor/rich-text-editor, lite-text-editor
  6. packages/ui
  7. web, space (parallel)
```

## Common Development Tasks

### Adding a new issue property
1. **Backend:** Add field to `Issue` model → migration → serializer → view
2. **Frontend:** Add type to `types/issues.d.ts` → add to store → add UI selector in `components/issues/sidebar-select/` → update filter constants

### Adding a new integration
1. **Backend:** Create models in `plane/db/models/integration/` → views → URLs → serializers
2. **Frontend:** Create service in `services/integrations/` → UI in `components/integration/`

### Debugging
- **Frontend:** React DevTools, MobX DevTools, browser console
- **Backend:** Django Debug Toolbar (local settings), `print()` / logging
- **API:** Check Nginx logs, Django request logging in BaseViewSet
- **Tasks:** Celery worker logs, Redis monitoring
