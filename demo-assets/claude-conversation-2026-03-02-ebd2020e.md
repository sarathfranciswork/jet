## Free Tier Analysis for ZipPath

### Fully Free Services

| Service | Free Tier | Concern? |
|---|---|---|
| **Flutter** | 100% free & open source | None |
| **Fastlane** | 100% free & open source | None |
| **Firebase Analytics** | Unlimited | None |
| **Firebase Crashlytics** | Unlimited | None |
| **Firebase Performance** | Free | None |
| **Firebase Remote Config** | Free | None |
| **Firebase Cloud Messaging** | Unlimited push notifications | None |

### Free But With Limits (Supabase)

| Resource | Free Tier Limit | Risk Level |
|---|---|---|
| Database | 500 MB | Medium — puzzles + users + groups add up |
| File Storage | 1 GB | Low |
| Auth MAUs | 50,000 | Low for launch |
| Edge Functions | 500K invocations/mo | Low |
| Bandwidth | 5 GB/mo | **High** — daily puzzles + realtime + leaderboards |
| Realtime connections | 200 concurrent | **High** — limits live leaderboard users |
| Projects | 2 max | Medium — no staging + prod separation |

### Free But Watch Out (GitHub Actions)

- **2,000 min/month** on free plan
- macOS runners (needed for iOS builds) have a **10x multiplier**
- That's effectively **~200 macOS minutes/month** → roughly **7-13 iOS builds/month**
- Android builds on Linux runners are fine

### NOT Free (Unavoidable Costs)

| Cost | Amount | Notes |
|---|---|---|
| **Apple Developer Program** | **$99/year** | Required to publish on App Store. No workaround. |
| **Google Play Developer** | **$25 one-time** | Required to publish on Play Store. |
| **Domain name** (for deep links) | **~$10-15/year** | Optional but the plan calls for deep links & sharing |

### Verdict

**Development phase — yes, fully free tier is viable.**

**Production deployment — no, not entirely.** You have two hard walls:

1. **~$134 minimum upfront** ($99 Apple + $25 Google + ~$10 domain) just to ship
2. **Supabase bandwidth (5 GB) and 200 concurrent Realtime connections** will be your first scaling bottleneck — likely hit around **1,000-2,000 daily active users**

### Recommendations to Stay Free Longer

- **Aggressive client-side caching** — the plan already calls for 24h puzzle pre-caching, which is great
- **Drop Supabase Realtime for leaderboards** — use polling every 30-60s instead to avoid the 200 connection cap
- **Minimize Edge Function calls** — validate client-side first, server-validate only on completion
- **Use GitHub Actions only for releases**, not every PR (or use a public repo for free unlimited minutes)

**Bottom line: ~$134/year minimum is unavoidable. Free tier works for development and soft launch (~1-2K users), but you'll need Supabase Pro ($25/mo) once you gain traction.**

Great question. For a Flutter mobile app like ZipPath, here are the practical approaches ranked by value:

## 1. Flutter Golden Tests (Built-in, Highest ROI)

Flutter's native `matchesGoldenFile` captures widget renders as reference images and fails if pixels change unexpectedly. This is the backbone of visual validation.

```dart
testWidgets('puzzle grid 5x5 renders correctly', (tester) async {
  await tester.pumpWidget(PuzzleGrid(size: 5, waypoints: mockWaypoints));
  await expectLater(
    find.byType(PuzzleGrid),
    matchesGoldenFile('goldens/puzzle_grid_5x5.png'),
  );
});
```

**What to cover for ZipPath:**
- Each grid size (5x5 through 8x8) in empty, partial, and completed states
- Path drawing states (active path, waypoint hit, wall collision)
- Share card rendering (spoiler-free visualization)
- Leaderboard layouts (empty, few members, full 50)
- Light mode vs. dark mode for every screen
- Colorblind mode variants

## 2. Alchemist Package (Better Golden Testing)

[Alchemist](https://pub.dev/packages/alchemist) wraps Flutter's golden tests with scenarios, themes, and device frames — much less boilerplate:

```dart
goldenTest('home screen', fileName: 'home_screen', builder: () {
  return GoldenTestGroup(children: [
    GoldenTestScenario(name: 'light', child: HomeScreen()),
    GoldenTestScenario(name: 'dark', child: HomeScreen(), theme: darkTheme),
    GoldenTestScenario(name: 'colorblind', child: HomeScreen(), theme: colorblindTheme),
  ]);
});
```

## 3. Integration Tests with Screenshots

For full-flow visual validation (not just widgets):

```dart
// integration_test/puzzle_flow_test.dart
testWidgets('complete puzzle flow', (tester) async {
  app.main();
  await tester.pumpAndSettle();
  
  await binding.takeScreenshot('01_home_screen');
  await tester.tap(find.text('Play'));
  await tester.pumpAndSettle();
  await binding.takeScreenshot('02_puzzle_active');
  // ... simulate path drawing ...
  await binding.takeScreenshot('03_puzzle_complete');
});
```

## 4. Maestro (Zero-Code Visual Flows)

[Maestro](https://maestro.mobile.dev/) runs on real devices/emulators with YAML-based flows and built-in screenshot comparison:

```yaml
appId: com.zippath.app
---
- launchApp
- takeScreenshot: home_screen
- tapOn: "Play"
- takeScreenshot: puzzle_active
- assertVisible: "5×5"
```

## 5. CI Pipeline Integration (GitHub Actions)

```yaml
# .github/workflows/visual-tests.yml
visual-tests:
  runs-on: macos-latest
  steps:
    - uses: subosito/flutter-action@v2
    - run: flutter test --update-goldens  # Generate on first run
    - run: flutter test                    # Compare on subsequent runs
    - uses: actions/upload-artifact@v4
      if: failure()
      with:
        name: golden-failures
        path: test/failures/
```

     ```dart
     /// Backtrack the path to the given cell, removing all cells after it.
     /// Returns null if the cell is not in the path or is the last cell.
     GameState? backtrackToCell(GameState state, int row, int col) {
       final index = state.path.indexWhere((p) => p.row == row && p.col == col);
       if (index < 0 || index >= state.path.length - 1) return null;

       final newPath = state.path.sublist(0, index + 1);
       final removedCells = state.path.sublist(index + 1);

       final newGrid = _copyGrid(state.grid);
       for (final cell in removedCells) {
         final waypointAtCell = _findWaypointAt(cell.row, cell.col);
         newGrid[cell.row][cell.col] =
             waypointAtCell != null ? CellState.waypoint : CellState.empty;
       }

       // Recalculate current waypoint index
       var waypointIndex = 0;
       for (final pos in newPath) {
         final wp = _findWaypointAt(pos.row, pos.col);
         if (wp != null) {
           waypointIndex = wp.order - 1;
         }
       }

       return state.copyWith(
         path: newPath,
         grid: newGrid,
         currentWaypointIndex: waypointIndex,
       );
     }
     ```

     ```dart
     void handleCellDrag(int row, int col) {
       if (state == null || _engine == null) return;
       if (state!.status == GameStatus.completed) return;
       if (state!.status == GameStatus.notStarted) return;

       // Skip if dragging over the current last cell
       if (state!.path.isNotEmpty &&
           state!.path.last.row == row &&
           state!.path.last.col == col) {
         return;
       }

       // Check if dragging backward over an existing path cell
       final backtracked = _engine!.backtrackToCell(state!, row, col);
       if (backtracked != null) {
         var newState = backtracked;
         if (newState.hintCell != null) {
           newState = newState.copyWith(hintCell: null);
         }
         state = newState;
         _saveGameState();
         return;
       }

       // Otherwise, try adding to path (forward movement)
       if (_engine!.canMoveToCell(state!, row, col)) {
         var newState = _engine!.addToPath(state!, row, col);
         if (newState.hintCell != null) {
           newState = newState.copyWith(hintCell: null);
         }
         state = newState;
         if (_engine!.isSolved(newState)) {
           _timer?.cancel();
           state = newState.copyWith(status: GameStatus.completed);
         }
         _saveGameState();
       }
     }
     ```
